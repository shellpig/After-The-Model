# 便利商店

> 便利商店 vertical slice（暫定 Phase 8）的場景設計檔。只記錄本場景的敘事、layout、互動物、關卡流程與開放時機。
> 系統規格（買賣/ShopPanel/commerce API）將寫入 `遊戲規格書.md`；實作契約寫入 `開發設計方針.md`；本檔為設計階段定稿，內容文字（對話樹、線索文案、catalog）標記為待填。

## 場景定位

街角一間**低端無人便利商店**——自動化、燈還亮著卻沒有人，廉價而孤獨。雨夜窗外霓虹冷光，CRT 廣告螢幕。

這是首次展示主角正職「**AI 善後員**」的關卡：玩家受派去修一台故障的店控機器人。表層是滑稽的身分錯亂，挖下去是一個被遺忘的人的回聲。

**核心母題**：失業恐懼 ×（失憶/遺忘）。一台機器「讀人讀到壞掉」，恰是主角自身（醒來失憶、靠線索拼回身分）的鏡像。

### 故障設定（關卡靈魂）

便利商店最後一個真人店員得知自己即將被辭退，自暴自棄、刻意不工作。店控機器人讀取了他遺留的日記記錄，不斷把那些記憶灌進自己的記憶體 → 當機，並**連同他「拒絕工作」的狀態一起繼承**，因此失去販賣功能、胡言亂語、以為自己就是那名店員。

## 關卡流程（全程）

```text
街上互動「外面販賣機」(前導線索，胡言亂語)
-> 進店對話「店內機器人」(淺層 babble)
-> 兩台都談過 -> 設 discovered_vendor_error
-> 回公寓用電腦
     第一次互動 = 舊內容 (work_ai_cleanup_role)
     第二次起 + discovered_vendor_error -> 工作 App 派工 -> QuestManager 開「維修販賣機器人」任務
-> 回店 examine 蒐證 (員工區線索) + 機器人深度診斷對話樹 (含誤導選項)
-> 對話揭示 -> 員工區「商店主機」變為可互動
-> 商店主機三段互動 -> 重置
     直接重置            : 恢復販賣；機器人日後口吻 = 純 AI 無機感
     先錄殘響再重置      : 取得殘響物品+筆記(不可賣)；機器人日後口吻 = 殘留一點人味
-> 通關 flag -> 店內 ShopPanel 開 + 外面販賣機連線恢復成迷你飲料商店
   (修復 message 暗示外面因連線也修好了)
```

## 已鎖定設計決策

| # | 項目 | 決定 |
|---|---|---|
| 1 | 商店結構 | 真・獨立室內場景（新 `.tscn`）；街道 `store_front` 改成門 → `transition_to` 進入 |
| 2 | 買賣 UI | 新增專用 `ShopPanel` + 新 `UIMode.SHOP`，不汙染容器系統 |
| 3 | 定價/庫存 | 固定價 + 有限庫存（買會扣減、進存檔）；通關事件解鎖商業 |
| 4 | 賣出 | 可賣背包任何有值物（`ITEMS_DB` 加 `value`；key_item 不可賣）；賣價 = 基礎價 × 全域折率；賣出不回補店庫存 |
| 5 | 買賣 gate | 修好前**完全不能買賣**；謎題是解鎖商業的唯一條件 |
| 6 | 任務系統 | 走正式 `QuestManager`（沿用晚的任務架構） |
| 7 | 對話路由 | 重用條件式對話路由（隨任務狀態分流：前導 babble / 診斷 / 修好後） |
| 8 | 機器人形體 | 放在櫃台上的一台機器（上半身/胸像感，非站立人型）；對話用立繪/螢幕臉呈現「人物」感與表情 |
| 9 | 拾遺抉擇 | 全對 + 蒐證齊全才解鎖「先錄殘響再重置」；否則只能直接重置；對話可反覆重來，主機按下重置前皆可逆 |
| 10 | 殘響物品 | 拾得 → 物品 + 筆記；用途日後再說、目前無用、**不可賣** |
| 11 | 存檔 | 店內 `can_save_here = true` |

## Layout（左 → 右）

```text
[貨架區] [自動門→街道] [自動熟食機台] [結帳櫃台+機器人] [飲料冷藏櫃] [員工區/置物櫃+商店主機] [後門(鎖)]
 flavor    出入口         flavor          核心互動區        flavor       線索密集區 + 修復裝置        未來鉤子
```

純 2D 側捲、角色只左右移動，鏡頭左右捲動。

- **貨架區**：正常、有在補貨的樣子（不破敗），位於門的左側。
- **自動門**：回街道轉場，位置偏左（不在最左端）。
- **自動熟食機台**：關東煮機 / 咖啡機 / 微波爐等，閃 error 的小機器，世界紋理。
- **結帳櫃台 + 機器人**：場景重心；機器人是櫃台上的胸像型機器，霓虹冷光打在這區。
- **飲料冷藏櫃**：冷光藍，呼應外面飲料商店。
- **員工區/置物櫃**：線索最密集；店員私人痕跡集中於此；**商店主機**亦在此（蒐證與修復同區，動線收斂）。
- **後門**：暫時打不開（互動只跳「鎖著」訊息），保留未來用途。

## 蒐證 / 診斷設計

- **線索物件 5 個**：店員置物櫃、店員日記殘頁、辭退通知/排班表、機器人銘牌、櫃台照片。
- 多數線索**接案後**才可 examine；少部分基礎物件（貨架、熟食機、冷藏櫃）接案前即可看，但只給與維修無關的淺顯 flavor。
- 每條證據揭示「機器人在模仿 / 根本以為自己是那名店員」。
- 診斷對話樹含**誤導選項**；唯有 examine 蒐證齊全 + 全程選對，才設 `understood_robot_truth` → 解鎖拾遺路徑。
- 對話可反覆重來；選錯/不齊時，對話結尾引導玩家去主機「直接重置」；只有正確對話才會知道能錄殘響。

## 機器人狀態機（對話內容隨狀態變）

| 狀態 | 條件 | 內容 |
|---|---|---|
| 前導 babble | 接案前 | 淺層胡言亂語，讓玩家察覺異常 |
| 深度診斷 | 接案後 | 深度對話樹，揭露店員故事 + 誤導選項 + 全對判定 |
| 修好（無機感） | 直接重置後 | 恢復販賣；ShopPanel 入口；口吻純 AI |
| 修好（人味） | 先錄殘響再重置後 | 恢復販賣；ShopPanel 入口；口吻殘留一點人味 |

## 商店主機三段互動

| 段 | 條件 | 行為 |
|---|---|---|
| 1 | 資訊不足 | 只說「這是主機」，主角不知如何維修 |
| 2 | 對話到一定程度（未全對） | 可執行**直接重置** |
| 3 | 對話全對（理解它「以為」自己是店員） | 出現兩選項：直接重置 / 先錄殘響再重置 |

重置（任一種）→ 設通關 flag + `complete_quest`；`store_robot_resolution`（reset / gleaned）驅動機器人日後口吻。

## 買賣系統（高階；細節入規格書/設計方針）

- 修好前店內**無法買賣**。
- 修好後與機器人互動 → repaired 招呼（依結局分流）→ 招呼結尾開 `ShopPanel`（左：店內貨架帶價格＋庫存；右：背包帶售出價；頂部 credits）。
- 外面販賣機修好後成第 2 個 `shop_id`（飲料 catalog），互動**直接開店、無對話**，驗證 data-driven 多商店。
- 買：扣 credits + 背包滿則擋 + 扣店庫存。賣：基礎價 × 折率 + 移除物品 + 加 credits；key_item 不可賣；殘響不可賣；已裝備物不可賣（需先卸下）。
